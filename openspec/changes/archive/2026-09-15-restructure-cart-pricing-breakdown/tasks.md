## 5. Trim fields not shown in either checkout mockup

After reviewing the two mockups (tax-excluded and tax-included) against the fields added in section 1, several fields turned out unused by either design. Trimmed from `CartResource.php`:

- [x] 5.1 Root `pricing`: remove `display_discount_total_money_object` (old combined product+order+shipping figure, superseded by `display_order_discount_money_object`), `display_shipping_subtotal_money_object`, `display_shipping_discount_money_object` (no separate shipping-discount row in either mockup), `display_shipping_total_money_object` (redundant with `display_shipping_amount_money_object` now that shipping tax lives in `tax_lines`), and `display_total_after_discount_money_object` (legacy, superseded by `display_order_total_money_object`). Also removed the now-dead `$this->base_subtotal`, `$this->base_discount_total`, `$this->base_shipping_total` property assignments, and `$this->base_shipping_tax` (already orphaned since section 1's shipping-tax removal, missed at the time).
- [x] 5.2 Per item: remove `display_pre_discount_subtotal_money_object`, `display_tax_amount_money_object`, per-item `tax_lines`, `display_discount_amount_money_object`, `display_total_money_object`, and `display_product_total_money_object` — none rendered per-line in either mockup; tax and discount only appear as root-level aggregates.
- [x] 5.3 Update `tests/Integration/CartApiTest.php` for the trimmed fields: `test_stacking_item_scoped_and_cart_wide_coupons` now sums `pricing.coupons[].display_discount_amount_money_object` instead of reading the removed `display_discount_total_money_object`; `test_cart_wide_coupon_discount_reconciles_across_multiple_items` now checks `display_order_discount_money_object` instead of the removed per-item `display_discount_amount_money_object` and root `display_discount_total_money_object` (this drops the fine-grained "per-item proportional split sums back exactly, even with fractional/odd prices" coverage that test previously had via the API — that invariant is now only implicitly covered, not directly asserted anywhere; flagging in case it's worth a dedicated `DiscountService` unit test later); `test_order_scoped_coupon_never_changes_line_item_display_price` now asserts `display_order_discount_money_object` > 0 instead of the removed per-item field; `test_total_after_discount_excludes_free_shipping_waiver_but_grand_total_still_reconciles` now uses `display_order_total_money_object` and `display_shipping_amount_money_object` instead of the two removed fields.
- [x] 5.4 Bug found and fixed during 5.3: `get_order_coupon_discount()` (added in section 1) summed `coupon_result->total_discount` for every `DiscountTarget::ORDER` coupon, but a free-shipping coupon defaults to `discount_target === ORDER` too and its `total_discount` equals its `shipping_discount` (money off shipping, not off the items subtotal) — so a free-shipping coupon was incorrectly inflating `display_order_discount_money_object`. Fixed to sum `total_discount - shipping_discount` per coupon, caught by `test_total_after_discount_excludes_free_shipping_waiver_but_grand_total_still_reconciles` failing ($80 instead of the expected $90) on first run.
- [x] 5.5 Verify: `php -l app/Resources/Cart/CartResource.php`, `vendor/bin/phpunit tests/Unit/Resources/CartResourceCouponFormattingTest.php` (15/15), `bash kirki-test integration --filter=CartApiTest` (29/29, all green after the 5.4 fix), `composer phpcs:wporg` on `CartResource.php` (clean), and a full grep sweep confirming only the two already-deferred files (`OrderCalculationResource.php`, `PageInlineScript.php`) still reference any removed field name.
