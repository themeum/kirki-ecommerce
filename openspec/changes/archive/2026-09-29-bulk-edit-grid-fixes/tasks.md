## 6. Real-browser bug fixes (diagnose live before fixing, per bulk-edit-grid-polish's Group 7 precedent)

- [x] 6.1 **Layout shift on selection**: diagnosed live via `getBoundingClientRect()`. Root cause: the fill-handle's `<Tooltip>` wrapper renders its trigger as an in-flow `inline-flex` `<span>` — even though the grabber inside it is `position: absolute` (zero footprint), that wrapper span still occupied its own line-box height (~18px) inside the cell's block flow, only appearing when a handle rendered (i.e. only on a selected cell), which is exactly why it looked like "selecting grows the cell." Fixed by passing `cssOverride={styles.grabberTrigger}` (`position: absolute`) to `Tooltip` in `bulk-edit-cell.tsx`, removing the wrapper from flow entirely. Verified: selected cell now measures exactly 32px via `getBoundingClientRect()`.
- [x] 6.2 **Grabber clipped**: found zero `overflow: hidden`/`clip` ancestors between the `<td>` and the grabber — this "clipping" was actually a visual side-effect of 6.1's layout shift (the taller cell + absolutely-positioned grabber visually colliding with the next row). Confirmed resolved as a consequence of the 6.1 fix; no separate `overflow` change was needed.
- [x] 6.3 **Horizontal scrollbar position and native scrollbar visibility**: diagnosed live. Root cause of the position bug: `<HorizontalScrollbar>` was rendered as a *sibling* of `#bulk-edit-scroll-container`, not nested inside it — so its `position: sticky; bottom: 0` had no relationship to the grid's own scroll box and stuck to the page instead. Fixed by moving it inside the container (`bulk-edit-table.tsx`), where its existing `left: 0; right: 0` sticky styles now correctly pin it to the container's own viewport in both scroll axes. Verified live: the scrollbar now sits directly under the last row regardless of scroll position. For native-scrollbar visibility, the existing `::-webkit-scrollbar:horizontal { display: none }` rule was confirmed present and correctly scoped (verified via `document.styleSheets`); added `scrollbar-width: none` for Firefox parity, noting in a comment that this also hides Firefox's vertical scrollbar (no custom vertical fallback exists) as an accepted trade-off.
- [x] 6.4 **Row borders not showing**: diagnosed live. Root cause: borders on `<tr>` are never painted by any browser's table rendering model — only `<td>`/`<th>` borders are, regardless of `border-collapse: separate`. Moving the border to `bulk-edit-cell.tsx`'s own `.cell` style (`borderBottom`, alongside the existing `borderRight`) hit a second, related quirk: a table cell's own border is painted *outside* its computed box regardless of `box-sizing: border-box`, so a `height: 32` cell with a 1px `borderBottom` rendered at 33px (confirmed via computed-style inspection; reducing the declared `height` had no effect, since `<tr>`'s own explicit `height: 32` — not the cell's — was the binding constraint). Fixed by using `boxShadow: inset 0 -1px 0 ...` instead of a real `border-bottom`, which paints inside the existing box and never affects layout size — the same reasoning `bulk-edit-grid-polish` already applied to the selection/fill indicator via `outline`. Verified: rows measure exactly 32px with both grid lines visible.
- [x] 6.5 Re-ran the full automated suite after all fixes: `npm run typecheck && npx vitest run` — clean, all passing (full `npm run lint` + final count captured in Group 7).
